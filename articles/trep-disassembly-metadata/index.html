Preparing an RGBDS Disassembly for TREP Generate reliable background-map metadata after every build

Contents

    Last edited: 08/2026
    Author: Tolstoj, with editorial assistance from AI

    TREP can use RGBDS .sym and .map files to find relocated graphics and labels in a modified Game Boy ROM. Linker files do not, however, describe a background map's width, height, or associated tile graphics. A small project metadata file supplies that missing information.

    This guide adds a post-build step that creates Project.trep.json. The generated file can be loaded into TREP together with the compiled ROM and linker files.

    What the Build Produces

    A TREP-ready build can produce these files:

    FilePurpose
    Project.gbThe compiled Game Boy ROM.
    Project.symFinal labels and their banked addresses.
    Project.mapLinker sections, labels, and unused ranges.
    Project.trep.jsonBackground-map dimensions, resolved starts, and tile-set assignments.
    Important: The JSON file is generated after linking. This ensures that relocated labels use their final ROM offsets.

    Prepare the Disassembly Labels

    Give every graphics block and background map a stable global label. Add an .end label wherever possible. TREP recognizes graphics labels beginning with Gfx_ and layout labels beginning with Layout_, GameScreenLayout_, or GameInnerScreenLayout_.

    Gfx_TitleScreen::
    INCBIN "gfx/title-screen.2bpp"
.end::

Layout_TitleScreen::
    INCBIN "layouts/title-screen.tilemap"
.end::

    The label name may be different, but using these conventions lets TREP recognize more data automatically. An explicit metadata definition will handle the details that cannot be inferred safely.

    Add the Generator

    Copy the TREP metadata generator into a tools directory in the disassembly. The generator requires Node.js and accepts four input paths:

    node tools/generate-trep-metadata.mjs Project.trep-source.json Project.sym Project.map Project.trep.json

    The script reads the final symbols, resolves every declared layout start, and writes a loadable TREP metadata file.

    Create the Project Definition

    Add Project.trep-source.json to the disassembly. This source file is maintained by the project and should be committed alongside the assembly source.

    {
  "format": "trep-source",
  "version": 1,
  "project": "My Game",
  "backgroundMaps": [
    {
      "name": "Title Screen",
      "symbol": "Layout_TitleScreen",
      "endSymbol": "Layout_TitleScreen.end",
      "width": 20,
      "height": 18,
      "tileSet": "Title Screen-Set",
      "filename": "title-screen.bin"
    }
  ]
}

    Definition fields

    FieldMeaning
    nameThe name shown in TREP.
    symbolThe global label at the first byte of the map.
    endSymbolAn optional label immediately after the map.
    widthThe map width in tiles.
    heightThe map height in tiles.
    tileSetThe TREP tile set used to render tile indexes.
    filenameThe suggested filename when exporting the map as binary data.

    Tile-set names

    TREP converts a graphics symbol such as Gfx_TitleScreen to the display name Title Screen and creates the tile set Title Screen-Set. The value in tileSet must match a tile set TREP can build from the selected linker files.

    If a screen combines ASCII and screen-specific graphics, keep the conventional Gfx_Ascii, Gfx_TitleScreen, and Gfx_MenuScreens names. TREP uses those groups to construct its combined title and menu tile sets.

    Add the Post-Build Step

    Makefile example

    PROJECT := MyGame
OBJECTS := main.o graphics.o layouts.o
TREP_GENERATOR := tools/generate-trep-metadata.mjs

$(PROJECT).gb $(PROJECT).sym $(PROJECT).map: $(OBJECTS)
	rgblink -o $(PROJECT).gb -n $(PROJECT).sym -m $(PROJECT).map $(OBJECTS)
	rgbfix -v -p 0 $(PROJECT).gb

$(PROJECT).trep.json: $(PROJECT).trep-source.json $(PROJECT).sym $(PROJECT).map
	node $(TREP_GENERATOR) $(PROJECT).trep-source.json $(PROJECT).sym $(PROJECT).map $(PROJECT).trep.json

.PHONY: all
all: $(PROJECT).gb $(PROJECT).trep.json

    PowerShell example

    rgblink -o MyGame.gb -n MyGame.sym -m MyGame.map main.o graphics.o layouts.o
rgbfix -v -p 0 MyGame.gb
node tools\generate-trep-metadata.mjs MyGame.trep-source.json MyGame.sym MyGame.map MyGame.trep.json

    Run the generator again whenever labels move, layouts change, or a new ROM is built.

    Load the Files into TREP

    Open TREP and add files by browsing or dropping them onto the start screen. Files may be added over several drops. TREP shows all expected file types and marks each supplied file with a checkmark.

    The Continue button accepts these combinations:

    • .gb only, using built-in addresses.
    • .gb, .sym, and .map, using automatic linker inference.
    • All four files, using the generated project metadata for reliable BG-map definitions.

    For a modified disassembly, all four files provide the most complete result.

    Validate the Result

    1. Open TREP's background-map editor.
    2. Confirm that every declared map appears by name.
    3. Check that each preview has the expected width and height.
    4. Verify that letters and graphics use the correct tiles rather than unrelated data.
    5. Export a map, then compare its byte count with width × height.
    6. After editing, save the modified ROM and test it in an emulator.

    Troubleshooting

    Missing symbol

    The generator stops if symbol or endSymbol is absent from the linker output. Make the label global with ::, check its spelling, and rebuild the object files before linking again.

    Unknown tile set

    TREP found the map but could not find the named tile set. Check the corresponding Gfx_ labels and the generated display name. The metadata value is case-sensitive.

    Correct dimensions but incorrect graphics

    The map points to the correct bytes but uses the wrong tile set. Change tileSet to the graphics group that is loaded into VRAM for that screen.

    Map starts correctly but includes an extra byte

    Some layouts have a terminator byte or linker padding after their tile data. Keep the declared width and height exact. The editable map size is determined by width × height, not by the distance to the next unrelated symbol.

    Keeping It Maintainable

    Keep addresses out of Project.trep-source.json. Store only stable symbol names and structural information there. The generator writes resolved addresses to Project.trep.json after every link, so relocated data never needs to be updated by hand.

    Commit the source definition and generator with the disassembly. The generated metadata may also be committed for releases or distributed beside the ROM patch, symbols, and linker map.
